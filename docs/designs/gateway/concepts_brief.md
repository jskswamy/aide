# Multi-Harness Custom Model Gateway Management (`aide gateway`)

* **Author:** jskswamy
* **Date:** 2026-10-27

## Overview

`aide` already isolates per-profile credentials and native agent directories, and routes environment variables per harness via `credentials.<name>.for.<harness>`. However, pointing coding agents at a custom-hosted LLM gateway today requires manual, error-prone steps for each harness: editing encrypted secret files in `$EDITOR`, hand-writing `for:` route blocks in `~/.config/aide/config.yaml`, and manually maintaining model catalogue files across every agent's config directory. Worse, environment variables alone only point Claude Code at a gateway URL--they do not populate Claude Code's `/model` picker (`gateway-models.json`), Pi's provider and model registry (`models.json`), OpenCode's provider map (`opencode.jsonc`), or Codex's model provider table (`config.toml`).

This feature introduces `aide gateway add|list|remove|sync` to configure custom-hosted LLM gateways on a profile and synchronize their `/v1/models` catalogue across all four profile-capable harnesses that support custom endpoints (`claude`, `pi`, `opencode`, and `codex`). Secret tokens stay exclusively in `aide`'s encrypted `age` store and are referenced by environment variable name in harness config files, while `aide` caches the normalized model catalogue locally and refreshes it on `add`, on `sync`, and automatically at launch when the configured refresh TTL expires.

## Analysis

### 1. Contrarian / YAGNI & Architecture (Skeptical Architect & Document Architect)
* **Do not duplicate `credentials:` routing**: `aide` already validates and injects per-harness credentials and endpoints through [`CredentialBinding`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/credentials.go#L24-L40). Creating a parallel credential injection path for gateways would split `aide which`, `aide status`, and [`Launcher.Launch`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/launcher/launcher.go#L204-L355). Instead, `aide gateway add` should generate a standard `credentials.<name>` entry (with `for:` routes for `claude`, `pi`, `opencode`, and `codex`) plus a lightweight `gateways.<name>` metadata block (`base_url`, `refresh_ttl`) on the profile.
* **Separate `internal/gateway` from `internal/provision`**: [`cmd/aide/sync.go`](file:///Users/subramk/source/github.com/jskswamy/aide/cmd/aide/sync.go#L57-L150) reconciles plugins, MCP servers, and hooks for a profile's single default `agent:`. Gateway model synchronization targets all four supported harnesses in the profile so switching harnesses (`aide --agent pi`, `aide --agent opencode`) works immediately. A focused `internal/gateway` package keeps model-catalogue fetching, caching (`~/.local/state/aide/gateways/<profile>/<gateway>.json` via [`statedir.Path`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/statedir/statedir.go#L27-L30)), and per-harness config merging independent of the single-agent plugin reconciler.

### 2. Codebase Integration Traps (Codebase Details Auditor)
* **Trap 1 -- [`Context.MarshalYAML`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/schema.go#L153-L206) drops unknown fields**: `Context.MarshalYAML` constructs an explicit map when serializing profiles to `~/.config/aide/config.yaml`. Any new `Gateways` field added to [`Context`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/schema.go#L110-L150) must be added to `Context.MarshalYAML` and blocked in [`projectDefiningKeys`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/profiles.go#L47-L56) so repository `.aide.yaml` files cannot define or redirect gateways.
* **Trap 2 -- [`checkDefaultRoutes`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/credentials.go#L193-L214) rejects conflicting default credentials**: `aide` fails config validation if two entries in `default_credentials:` set the same environment variable for the same harness. Because a gateway route sets `ANTHROPIC_AUTH_TOKEN`, `ANTHROPIC_BASE_URL`, and `ANTHROPIC_API_KEY: ""`, appending a gateway to `default_credentials:` when `anthropic` or another gateway is already in `default_credentials:` will fail validation. `aide gateway add` must replace the conflicting default entry (or offer `--no-default` so secondary gateways can be selected via `aide --credential <name>`).
* **Trap 3 -- Unisolated default profiles (`SelectsConfigDir() == false`)**: In a single-profile config where `config_dir_name` (`ctx.Profile`) is unset ([`Context.SelectsConfigDir`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/profile_dirs.go#L14-L16)), `aide` launches harnesses against their global directories (`~/.claude`, `~/.pi/agent`, `~/.config/opencode`, `~/.codex`) rather than `~/.<harness>-<profile>`. If `aide gateway add` writes to `~/.<harness>-<profile>` without setting `config_dir_name: <profile>` (or matching [`launchConfigDir`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/launcher/native_auth.go#L66-L78)), the launched agent will look in the wrong directory and miss the synced models.
* **Trap 4 -- Programmatic `age` secret writes and YAML serialization**: [`Manager.Edit`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/secrets/manager.go#L254-L321) opens `$EDITOR` and concatenates decrypted keys with raw strings (`k + ": " + v + "\n"`), which corrupts tokens containing colons or `#`. `Manager` needs a non-interactive `SetKey` method that serializes key-value maps via `yaml.Marshal` and derives the `age` public recipient from the discovered identity ([`DiscoverAgeKey`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/secrets/age.go)) when creating a new store.
* **Trap 5 -- Environment scrub registry**: `CLAUDE_CODE_ENABLE_GATEWAY_MODEL_DISCOVERY` is not currently listed in `providerSelectorNames` in [`internal/envscrub/envscrub.go`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/envscrub/envscrub.go#L35-L44). Adding it prevents shell leaks across profiles and blocks untrusted `.aide.yaml` files from setting it.

### 3. Cost, Latency & Operational Visibility (Design Critic & Comprehension Reviewer)
* **Launch-time refresh latency and offline fallback**: Refreshing `{base_url}/v1/models` during `aide` launch when the cache is older than `refresh_ttl` adds network latency before the agent TUI starts, and corporate gateways often require VPNs or macOS system proxy/CA trust.
  * Launch-time refresh must print clear progress (`Refreshing gateway '<name>' models from <base_url>...`) before handing off to the harness.
  * If the gateway is unreachable at launch and a cached catalogue already exists on disk, `aide` must warn and fall back to the existing cache rather than blocking the session.
  * Reuse the token already decrypted by `ResolveCredentialEnv` during launch so launch-time refresh never decrypts the `age` secret file twice.
* **TLS / Corporate Proxy compatibility**: Go's `net/http` on macOS reads system roots via Security.framework, but corporate PAC (Proxy Auto-Config) scripts are not evaluated by Go's `http.ProxyFromEnvironment`. Supporting standard `HTTPS_PROXY` via `http.DefaultTransport` (or falling back to `curl` when configured/needed on macOS) avoids silent gateway connection failures on managed networks.

### 4. Per-Harness Config Mutation & Cleanup (Implementation Readiness Reviewer)
Each harness requires non-destructive read-modify-write semantics so user settings, MCP servers, and plugins are preserved on `sync` and `remove`:
* **Claude Code (`<claude-dir>/cache/gateway-models.json`)**: Single file keyed by `baseUrl`. Note that if a user switches between two gateways on the same profile via `aide --credential <gw2>`, `Launcher.Launch` must materialize `<gw2>`'s cached models into `cache/gateway-models.json` before `claude` starts because Claude Code only reads that single file path.
* **Pi (`<pi-dir>/models.json`)**: Updates `providers.<gateway>` (`baseUrl`, `apiKey: "ANTHROPIC_AUTH_TOKEN"`, `authHeader: true`, `api: "anthropic-messages"`, `models: [...]`) while preserving other providers. Also note Pi's auth precedence: if `<pi-dir>/auth.json` has a saved login for the same provider key, Pi prefers `auth.json` over env vars.
* **OpenCode (`<opencode-dir>/opencode.jsonc`)**: Parses JSONC via `hujson.Standardize` (matching [`internal/provision/mcp/opencodejson.go`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/provision/mcp/opencodejson.go)) and updates `provider.<gateway>` (`npm: "@ai-sdk/anthropic"`, `options.baseURL`, `options.apiKey: "{env:ANTHROPIC_AUTH_TOKEN}"`, `models`) without disturbing `mcp` or `plugin` keys.
* **Codex (`<codex-dir>/config.toml`)**: Parses TOML via `go-toml/v2` (matching [`internal/provision/mcp/codextoml.go`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/provision/mcp/codextoml.go)) and updates `[model_providers.<gateway>]` (`name`, `base_url`, `env_key = "ANTHROPIC_AUTH_TOKEN"`, `wire_api = "chat"`). Because Codex speaks OpenAI `chat`/`responses` wire protocols rather than Anthropic `/v1/messages`, this requires the gateway to also serve `/v1/chat/completions` (or `/v1/responses`) at `base_url`.

## Goals vs. Non-Goals

* **In-Scope Goals:**
  * Add `aide gateway add|list|remove|sync` commands with human and `--format json` output.
  * Store gateway tokens in `aide`'s encrypted `age` secret store programmatically (supporting masked interactive input, `--token`, or `--token-stdin`) without opening `$EDITOR`.
  * Configure `credentials.<name>.for` routes and `gateways.<name>` metadata (`base_url`, `refresh_ttl`) on the target profile in `~/.config/aide/config.yaml`.
  * Fetch `{base_url}/v1/models`, normalize LLM entries, and cache them in `~/.local/state/aide/gateways/<profile>/<gateway>.json`.
  * Materialize non-secret provider and model definitions into `claude` (`cache/gateway-models.json`), `pi` (`models.json`), `opencode` (`opencode.jsonc`), and `codex` (`config.toml`) during `add`, `sync`, and at launch when stale or when switching harnesses/credentials.
  * Display visible progress during gateway sync and launch-time TTL refresh, with graceful fallback to cached models if offline at launch.
* **Out-of-Scope Non-Goals:**
  * Supporting vendor-locked harnesses that do not accept custom gateway endpoints or model catalogues (`agy` / Antigravity, `copilot`, `cursor-agent`, `amp`, `gemini`).
  * Supporting harnesses without profile-directory isolation in `aide` (`aider`, `goose`).
  * Writing plaintext bearer tokens into any harness configuration file (`models.json`, `opencode.jsonc`, `config.toml`, `settings.json`).
  * Defining gateways inside repository-scoped `.aide.yaml` files.

## Key Decisions & Staging for Next Steps

1. **CLI Surface**: `aide gateway add [<name>] --url <url> [--token <token>] [--ttl 24h] [--profile <profile>]`, `aide gateway sync [<name>]`, `aide gateway list [--models]`, and `aide gateway remove <name>`.
2. **Storage Split**: Bearer token is stored in `~/.config/aide/secrets/<store>.enc.yaml`; `base_url` and `refresh_ttl` are stored in `~/.config/aide/config.yaml`; normalized model catalogue is cached in `~/.local/state/aide/gateways/<profile>/<gateway>.json`.
3. **Open Decisions to Resolve Before Drafting**:
   * **Default credential replacement**: When `aide gateway add` runs on a profile that already has `default_credentials: [anthropic]` or another gateway, should it replace that default automatically (unless `--no-default` is passed) so [`checkDefaultRoutes`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/config/credentials.go#L193-L214) does not fail?
   * **Single-profile directory resolution**: When a user runs `aide gateway add` on a profile where `config_dir_name` is unset (`SelectsConfigDir() == false`), should `aide` write to the harness's default directory (`~/.claude`, `~/.pi/agent`, `~/.config/opencode`, `~/.codex`) matching [`launchConfigDir`](file:///Users/subramk/source/github.com/jskswamy/aide/internal/launcher/native_auth.go#L66-L78), or automatically set `config_dir_name: <profile>` so files live in `~/.<harness>-<profile>`?
   * **Codex wire protocol**: Since Codex only speaks OpenAI `chat` / `responses` and cannot talk to an Anthropic-only `/v1/messages` endpoint, should `[model_providers.<gateway>]` in `config.toml` default to `wire_api = "chat"` with `base_url = "<gateway_url>/v1"`?
